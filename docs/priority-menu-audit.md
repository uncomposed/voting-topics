# Priority menu editorial audit

## Source and purpose

The archived `starter-pack.v2.4.json` contains 154 items under 22 broad topics. The topics are retained only as presentation categories. The first MVP catalog synthesizes 66 reusable priorities from that editorial input and an explicit omission review.

This is an editorial recovery, not a restoration of the old scoring hierarchy. Old topic importance, stance, relations, and item stars do not enter the menu or a user’s calculations.

## Acceptance test

Each menu entry must:

1. express one outcome rather than a broad issue bucket;
2. state a direction in which the user could want the outcome to move;
3. avoid prescribing a candidate, bill, institution, or policy mechanism;
4. be understandable without hidden category weight;
5. be meaningfully assessable against at least some election options.

## Omission and perspective check

The catalog includes outcomes that can compete or coexist. For example, firearm harm reduction and protection from credible threats are separate priorities; public-service sufficiency and predictable tax burdens are separate priorities. This is intentional. A menu item is not required to be ideologically neutral, but the menu must not hide recognizable competing outcomes.

Archived items not represented in revision 1 are deferred rather than silently rejected. Most are candidates for later inclusion after duplicate, compound-outcome, jurisdiction-specific, or solution-language review. Their source bytes remain recoverable from repository history at `archive/pre-trusted-guide-pivot`.

## Change policy

- Existing item ids and revisions are stable.
- A wording change increments the item revision.
- Profiles copy the selected statement and origin revision, so a menu update never silently rewrites user priorities.
- Removing an item from a future menu does not remove it from existing profiles.
- Editorial changes require an omission/perspective review and a changelog entry here.
